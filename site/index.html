个人 Agent 运行时A personal agent runtime

记得住，
也守得住。 It remembers.
The line holds.

Tree-Agent 把 pi 编码代理包在属于你的一层里。消息先写成编号事件，任务进入 SQLite 队列，再交给一次性的 pi 子进程。命令行、Web、飞书和 QQ 共用这一份记忆。 Tree-Agent is the layer around the pi coding agent that belongs to you. A message becomes a numbered event, a task enters a SQLite queue, and a one-shot pi child process does the work. The CLI, web, Feishu, and QQ share that memory.

能力What it does

聊天壳子没有的三样东西。Three things a chat window does not have.

状态留在编排层。边界留在子进程。内核可以换，平台逻辑是你的。 State stays in the orchestrator. The boundary stays on the child process. The kernel can be swapped. The platform logic is yours.

  1. 01

    队列扛得住崩溃The queue survives a crash

    任务、事件、结果写在 SQLite 里，使用 WAL。执行器被杀掉或重启，领取的位置还在。Tasks, events, and results live in SQLite with WAL. Kill or restart the executor and the place it left off is still there.

  2. 02

    一次性的 pi 子进程A one-shot pi child

    执行器不连数据库，不占服务端口。两边用 JSONL 说话：stdin 进去，stdout 出来。等的是 agent_settled，不是单独的一次 agent_end。The executor has no database and opens no service port. It speaks JSONL: stdin in, stdout out. The runtime waits for agent_settled, not a single agent_end.

  3. 03

    证据才算记忆Memory needs evidence

    每条记忆绑到一条编号事件和逐字引文，而且引文必须来自用户消息。置信度不够只存 tentative，不注入。凭据形状的内容在写入边界被拒绝。Each memory is tied to one numbered event and a verbatim quote, and the quote has to come from a user message. Low confidence stays tentative and is never injected. Credential-shaped writes are refused at the boundary.

  4. 04

    通道只是运输Channels are transport

    命令行、Web、飞书长连接、QQ 的 OneBot v11，以及 Telegram，走同一条 ingest。重投的消息用 claimMessage 丢掉，不会变成第二条记忆。The CLI, web, Feishu long connection, QQ over OneBot v11, and Telegram all call ingest. A redelivered message is dropped by claimMessage instead of becoming a second memory.

  5. 05

    技能与 MCPSkills and MCP

    技能是磁盘上的 SKILL.md，运行时只读 frontmatter，不执行它。MCP 用 pi 自己的客户端。只读沙箱会关掉全部 mcp__* 工具。A skill is a SKILL.md on disk. The runtime reads its frontmatter and does not execute it. MCP uses pi’s own client. Readonly mode turns every mcp__* tool off.

  6. 06

    人格、提醒、短状态Persona, reminders, short state

    SOUL.md 管怎么说，CONTRACTS.md 管怎么干，两份预算分开。提醒写在回复里的控制指令上，到点由运行时推送。端口、分支这种只活几天的事，用带 TTL 的短期状态，同步落库。SOUL.md is how it speaks. CONTRACTS.md is how it works. They have separate budgets. A reminder is a control line in the reply, and the runtime pushes it when it is due. Ports and branches live as short state with a TTL, written synchronously.

路径How a turn runs

从一句话到一次回复。From one sentence to one reply.

  1. 1

    接入Ingest

    任何通道先把消息交给 ingest。模型还没被叫到，证据已经在 conversation_events 里，带编号。Every channel hands the message to ingest. Before the model is called, the evidence is already a numbered row in conversation_events.

  2. 2

    队列Queue

    任务写进 SQLite。worker 逐个领取。崩溃之后可以再领，不会因为进程没了就丢掉位置。The task is written to SQLite. A worker claims one at a time. After a crash it can claim again. The place is not lost with the process.

  3. 3

    执行Run

    runTask 拉起 pi --mode rpc。上下文在这一刻组装：记忆、短状态、摘要、窗口。子进程不碰数据库。runTask starts pi --mode rpc. Context is composed at that moment: memory, short state, summary, window. The child never touches the database.

  4. 4

    回复Reply

    文字写回原来的通道，并再记一条事件。Web 用 SSE 把状态、工具和文本增量推给浏览器。The text goes back on the same channel, and another event is stored. The web channel pushes status, tools, and text deltas over SSE.

通道Where it lives

同一个人，同一份记忆。One person. One memory.

  • 01

    CLI

    ask 入队并立刻跑。worker 是守护进程，逐个领任务。doctor 跟 pi 握手，看模型有没有绑上。ask enqueues a task and runs it. worker is the daemon that drains the queue. doctor handshakes with pi and shows whether a model is bound.

    node src/cli.ts ask "…" --cwd .
  • 02

    Web

    本机 HTTP 加 SSE，不是第二套运行时。默认只听 127.0.0.1:8788。离开 loopback 必须自己设置 PI_RT_WEB_TOKEN。界面在 web/。Local HTTP plus SSE, not a second runtime. It listens on 127.0.0.1:8788 unless you move it. Leaving loopback requires PI_RT_WEB_TOKEN. The UI lives in web/.

    node src/cli.ts serve --channel web
  • 03

    飞书Feishu

    长连接，只需要出站 TLS，不要公网 IP、域名或证书。也保留了可本地演练的 webhook 模式。目前只接文本消息。A long connection that only needs outbound TLS. No public IP, domain, or certificate. A webhook mode remains for local drills. Text messages only, for now.

    node src/cli.ts serve --channel feishu
  • 04

    OneBot

    QQ 走 OneBot v11：WebSocket 收，HTTP 发。群里默认只有真正 @ 到它才回复。NapCat 或 Lagrange 都可以。QQ speaks OneBot v11: WebSocket in, HTTP out. In a group it answers a real @ by default. NapCat or Lagrange both work.

    node src/cli.ts serve --channel qq

Telegram 也是一条长轮询通道，需要 TELEGRAM_BOT_TOKEN。本地可以用 feed 模拟某个说话人。 Telegram is there too, as long polling with TELEGRAM_BOT_TOKEN. feed can simulate a speaker locally.

记忆 · 技能 · MCPMemory, skills, MCP

记什么，和能调用什么，是两回事。What it remembers is not what it can call.

记忆Memory

三层：证据、主体、裁决。动作是 create、correct、invalidate、contest。有争议的行不注入。偏好槽位让新的说法盖过旧的；跨槽位用可信度乘时效，打平就标 contested。默认检索是离线的 hash embedding，只抓字面相似。把 EMBEDDING_BASE_URL 指到兼容接口之后，才走那套向量。知识库和记忆分开，文档不能伪装成你说过的话。Three layers: evidence, subject, verdict. The actions are create, correct, invalidate, and contest. Contested rows are not injected. Preference slots let the newer statement win. Across slots, credibility times recency, and a near-tie is contested. Search defaults to an offline hash embedding, which only catches surface similarity. Point EMBEDDING_BASE_URL at a compatible endpoint when you want real vectors. The knowledge base stays separate, so a document cannot pretend to be something you said.

技能Skills

按 Agent Skills 的路径找 SKILL.md：用户目录，以及从仓库根到当前工作区的项目目录。同名时近处的项目技能盖过用户技能。扫描器只读 frontmatter。pi-rt skills 用来核对这台机器上实际有哪些，避免一个写错的目录看起来像模型自己不用。SKILL.md files are discovered the Agent Skills way: the user directory, then project directories from the repo root down to the working directory. The nearer project skill wins a name clash. The scanner only reads frontmatter. pi-rt skills lists what this machine actually has, so a mistyped folder does not look like a skill the model ignored.

MCP

协议不用重写，pi 已经是客户端。仓库里有手写的 server：fetch 与 search、memory_search、知识库，以及 fanout、orchestrate、便签、文件锁、send、propose_self_edit。调度只在运行时一处，server 是薄客户端。只读模式排除 mcp__*，因为别人声明的工具我们查不了它会不会写。The protocol is not reimplemented. pi is already the client. This repo ships hand-written servers: fetch and search, memory_search, knowledge, plus fanout, orchestrate, notes, file locks, send, and propose_self_edit. One runtime owns scheduling. Servers are thin clients. Readonly mode excludes mcp__*, because a server declares its own powers and we cannot see whether it writes.

自托管On your machine

没有账号系统。坐在这台机器前的人就是主人。No accounts. The person at this machine is the owner.

磁盘Disk

数据库是 data/runtime.db。模型凭证在 data/pi，和 ~/.pi 分开。子进程只拿一份收窄过的环境变量，shell 里 echo 不到飞书密钥。The database is data/runtime.db. Model credentials live in data/pi, apart from ~/.pi. The child gets a narrowed environment, so a shell cannot echo a Feishu secret.

网络Network

飞书用出站长连接。Web 默认绑在 loopback；要绑到别处，必须自己设置令牌。本地控制 API 在 127.0.0.1:8899，没有鉴权，也不该被暴露出去。Feishu uses an outbound long connection. Web binds to loopback unless you set a token yourself. The local control API is 127.0.0.1:8899, with no auth, and it should not be exposed.

边界Boundary

readonly、safe、full 是工具裁剪，不是容器。safe 没有 bash。readonly 连 MCP 一起关。read 仍能读你能读的文件。真正的隔离需要容器或虚拟机。readonly, safe, and full trim tools. They are not a container. safe has no bash. readonly also turns MCP off. read can still open any file you can open. Real isolation needs a container or a VM.

单实例。SQLite 加一条长连接，不能水平扩容。图片、文件和语音目前会跳过，而不是假装解析了。 One instance. SQLite plus one long connection does not scale out. Images, files, and audio are skipped today, rather than parsed badly.

FAQ

问得具体一点。The specific questions.

它是 pi 的另一个发行版吗？Is this a fork of pi?

不是。产品名是 Tree-Agent，内核是 @earendil-works/pi-coding-agent，用 RPC 子进程调用。外面这一层加上队列、记忆、通道和工具治理。npm 包名是 tree-agent。路径和容器名里的 pi-runtime / pi-rt 留着，是为了不打断已经在跑的部署。命令行入口仍是 node src/cli.ts。No. The product is Tree-Agent. The kernel is @earendil-works/pi-coding-agent, called as an RPC child process. This layer adds the queue, memory, channels, and tool governance. The npm package name is tree-agent. Paths and container names still say pi-runtime / pi-rt so existing deployments keep running. The command is still node src/cli.ts.

模型和数据各在哪？Where do the model and the data live?

编排在你的机器上。数据库是 data/runtime.db。模型走你自己登录的 provider，凭证放在 data/pi，不写进 ~/.pi。运行时不提供一个托管账号。Orchestration is on your machine. The database is data/runtime.db. The model is whichever provider you log in to. Credentials stay in data/pi, not ~/.pi. There is no hosted account.

几个通道会不会记成好几个人？Do the channels become several people?

主人由配置决定，ownerName 或 PI_RT_OWNER，不是谁先说话谁就是主人。PI_RT_OWNER_IDS 可以把飞书、Telegram 上的另一个 id 也算成同一个人。手写记忆全局可见，从某个会话提炼的记忆留在那个线程。The owner is configured, ownerName or PI_RT_OWNER, not whoever speaks first. PI_RT_OWNER_IDS can mark another Feishu or Telegram id as the same person. Hand-written memories are global. Memories distilled from a thread stay on that thread.

每句话都会变成事实吗？Does every sentence become a fact?

不会。默认攒够一批，或线程闲置一段时间，才提炼。引文必须是那一条用户消息的子串。助手的复述不算证据。争议中的行不会被塞进提示词。No. Distillation waits for a batch, or for a thread to sit idle. The quote must be a substring of that one user message. The assistant restating something is not evidence. Contested rows are not put into the prompt.

沙箱能挡住什么？What does the sandbox actually stop?

它去掉工具，而不是把进程关进容器。safe 是默认，没有 bash。readonly 不能写，并且关掉 MCP。full 才有 shell，同时环境变量是收窄的。处理不可信任务时，只有 readonly 勉强算安全。It removes tools. It does not jail the process in a container. safe is the default, and it has no bash. readonly cannot write, and MCP is off. full is the mode with a shell, and the environment is still narrowed. For untrusted work, only readonly is even close to safe.

能多机扩容吗？Can it scale out?

不能。一台机器，一个 SQLite，一条长连接。这是个人运行时的形状，不是集群。No. One machine, one SQLite file, one long connection. That is the shape of a personal runtime, not a cluster.
